## Goal
Persist the M2 model to the PDF: `flush()` writes every annotation as a proper `/Annots` entry with a generated `/AP /N` form XObject via lopdf incremental save, the render worker swaps to the new revision without flicker, pre-existing annotations are imported into the model on open, and the sample app can Save / Save As. No forms editing (M4), no signatures (M5).

## Known pitfalls carried over from M0–M2 (toolchain + design facts — do not rediscover them)
- **AGP 9.5.0 / Gradle 9.8.2, built-in Kotlin, new DSL.** Do not apply `org.jetbrains.kotlin.android`; `org.jetbrains.kotlin.plugin.compose` and `org.jetbrains.kotlin.plugin.serialization` (2.4.21) are applied to `nib-android` and work with built-in Kotlin. `android.ndkDirectory` does not exist — use `androidComponents.sdkComponents.ndkDirectory`. Source-set additions use `sourceSets.<name>.{jniLibs,kotlin,assets}.directories.add(...)` plus explicit task `dependsOn`; fixtures are shared via `assets.directories.add("../nib-rs/nib-core/tests/fixtures")`. `compileSdk = 37`, `targetSdk = 36`. Configuration cache is **on**. `testOptions.unitTests.isReturnDefaultValues = true` is set (Compose `Path` in JVM tests).
- **UniFFI 0.32.2**: `uniffi-bindgen generate <lib>` takes the library path positionally. Bindings come from the host **debug** `libnib_ffi` — run `./gradlew :nib-android:uniffiBindgenDebug` and read `nib-android/build/generated/uniffi/debug/uniffi/nib_ffi/nib_ffi.kt` for exact Kotlin types (`u32→UInt`, `u64→ULong`, `Vec<u8>→ByteArray`, `Option<String>→String?`, errors → `NibException.<Variant>` with fields `v1`/named). Callback interfaces (`FontProvider`, `AssetProvider`) are new in M3: UniFFI callbacks run on the calling Rust thread — the `Nib.init` `CallbackThreadInitializer` already keeps JNA threads attached; keep the callbacks synchronous and cheap, never call back into `NibDocument` from inside them (the engine mutex is held).
- **UniFFI async + JNA**: Kotlin continuations resume **on the Rust worker thread**. Never send a oneshot reply while holding the queue lock; `RenderWorker::bump_generation` is synchronous under the lock.
- **Render worker**: one process-wide `RenderWorker` (`OnceLock` in `nib-ffi/src/document.rs`); documents are `u64` handles. New pdfium-touching features must be `Ctrl` messages handled in `nib-render/src/renderer.rs` (pattern: `Ctrl::CharBoxes` added in M2). `Renderer::swap(id, bytes)` + `DocSlot {current, previous}` already implement the ≤ 2-resident revision swap. `page.boundaries().crop()` errors when `/CropBox` is absent — fall back to the media box.
- **Pixels are RGBA** (`FPDF_REVERSE_BYTE_ORDER`), copied with `Bitmap.copyPixelsFromBuffer` — no swizzle.
- **Delta engine facts**: `Engine::apply(Vec<Op>)` = one undo step; validation is atomic per call (nothing applied on any error, errors returned as `DeltaError::Invalid(Vec<ValidationError>)` → `NibError::InvalidDelta(json)`). `create` payloads omit `id`/`page` — the engine injects `op.id`/`op.page` before deserializing. `rect` is computed from geometry when absent (`dirty::bbox`). Coalescing merges consecutive single-key `rect/strokes/value/quadPoints/start/end` updates < 500 ms apart (by op `ts`); undo of a coalesced unit reverts the whole unit. `redo()` appends fresh-`opId` copies to `history` (Full export replays exactly). Undo of a delete re-inserts at the **end** of z-order (`Model.order`) — if the writer needs positional `/Annots` order, fix it in the engine first. `Engine.base: Model` is the hook for annotations imported from the PDF (empty in M2); Compacted export diffs `base → model`. `Model.revision` is always 0 so far; `import` rejects `baseRevision ≠ revision` unless `rebase`.
- **Schema**: `nib-core/schema/nib-delta.schema.json` is generated; `tests/schema.rs::schema_is_up_to_date` fails on drift (regenerate with `cargo test -p nib-core --test schema schema_regenerate -- --ignored`); every fenced ```json block in `docs/JSON_SCHEMA.md` must stay strictly valid JSON and classifiable (envelope / Op / Op[] / Annotation / FormField / SignatureEntity) or `schema_examples_validate` panics telling you why. `insta` snapshots live in `nib-core/src/delta/snapshots/`.
- **Compose overlay facts**: `NibPdfView` gates scroll/pinch/double-tap on `state.tool == Tool.Pan`; `PageItem` composes tiles → `AnnotationOverlay` → one tool overlay → tile semantics boxes. `PageTransform.kt` mirrors `geom/transform.rs` (content px = pt × density × zoom, y-down, page top-left origin; `state.transform(page)`, `state.pageOriginInView(page)`). Annotations expose `contentDescription = "annotation:<Subtype>"` + `testTag("annot:<id>")`. `HistoricalChange.pressure` does **not** exist in Compose ui 1.12.1 — historical ink samples reuse the current change's pressure. Stylus pressure in tests is injected via `decorView.dispatchTouchEvent` with `MotionEvent.TOOL_TYPE_STYLUS` (`M2TestSupport.kt`) — no uiautomator dependency. The sample-app palette row 2 overflows and scrolls horizontally; `Stamp…`/`Export` are off-screen on a Pixel 6 until scrolled; a swipe starting on the stroke `Slider` moves the thumb, and swipes at x ≥ 1050 trigger system Back.
- **Highlight snapping**: `text_lines_in_rect` groups pdfium `loose_bounds()` char boxes by baseline (`nib_core::text::snap_lines`); Helvetica 12 pt lines in `text.pdf` come out ≈ 13–14 pt tall with 16 pt pitch; quads are emitted `[UL, UR, LL, LR]` y-up.
- **Tests on device**: `createAndroidComposeRule<ComponentActivity>()`, `performTouchInput { swipe()/pinch()/click() }` work; set `state.tool` before gestures. 20 `swipeUp()` do not reach page 99 — `NibPdfViewTest` scrolls programmatically. Emulator `nib_api34` is often still running — check `adb devices` first. Debug builds compile only the host ABI; release `lto = "fat"` ×3 ABIs takes minutes — iterate on debug, run release only at the DoD gate. R8 keep rules for kotlinx.serialization live in `nib-android/consumer-rules.pro` (verified on the minified sample).
- cargo-ndk also emits `libpdfium_render-*.so`; `copyRustJniLibs<Variant>` filters to `libnib_ffi.so` — keep that filter. `deny.toml` has per-crate MPL-2.0 exceptions for `uniffi*` and ignores `RUSTSEC-2026-0374`; `cargo deny` warns on duplicate `nom`/`syn` versions (accepted).
