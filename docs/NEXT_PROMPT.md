## Goal
A working **annotation editor without persistence**: every op from JSON_SCHEMA validates and applies to an in-memory model in Rust (`nib-core::model`, `nib-core::delta`) with undo/redo, export/import; the Compose layer captures ink and creates highlights/shapes/free text/sticky notes/stamps, draws them in an overlay (the reference renderer), supports select/move/resize/delete, and the sample app exposes a tool palette and a JSON export share sheet. Annotations vanish on reopen — by design (writing is M3).

## Known pitfalls carried over from M0/M1 (toolchain facts — do not rediscover them)
- **AGP 9.5.0 / Gradle 9.8.2, built-in Kotlin, new DSL.** Do not apply `org.jetbrains.kotlin.android`; `org.jetbrains.kotlin.plugin.compose` is applied to `nib-android` and `sample-app`. `android.ndkDirectory` does not exist — use `androidComponents.sdkComponents.ndkDirectory`. Source-set additions use `sourceSets.<name>.{jniLibs,kotlin,assets}.directories.add(...)` plus explicit task `dependsOn` (see `nib-android/build.gradle.kts`); fixtures are shared with Android tests/sample via `assets.directories.add("../nib-rs/nib-core/tests/fixtures")`. `compileSdk = 37`, `targetSdk = 36`. Configuration cache is **on**.
- **UniFFI 0.32.2**: `uniffi-bindgen generate <lib>` takes the library path positionally. Bindings are generated from the host **debug** `libnib_ffi` (`bindgenLib<Variant>`) — run `./gradlew :nib-android:uniffiBindgenDebug` and read `nib-android/build/generated/uniffi/debug/**/nib_ffi.kt` for exact Kotlin types (`u16→UShort`, `i8→Byte`, `u64→ULong`, `Vec<u8>→ByteArray`). `cargo ndk` / `cargo metadata` must run inside `nib-rs/`.
- **UniFFI async + JNA**: Kotlin continuations are resumed **on the Rust worker thread**. `Nib.init` registers `Native.setCallbackThreadInitializer(uniffiRustFutureContinuationCallbackImpl, CallbackThreadInitializer(true, false))` — keep it, or ART aborts with "attempting to detach while still running code". In Rust, never send a oneshot reply while holding the queue lock (the inline wake re-enters the worker → deadlock); `RenderWorker::bump_generation` is synchronous under the lock and returns the new generation.
- **Render worker**: one process-wide `RenderWorker` (`OnceLock` in `nib-ffi/src/document.rs`); documents are `u64` handles. New pdfium-touching features (char boxes for highlight snapping) must be new `Ctrl` messages handled in `nib-render/src/renderer.rs`, never direct pdfium calls from `nib-ffi`. `page.boundaries().crop()` errors when `/CropBox` is absent — fall back to the media box. `pdfium_probe` treats `PdfiumLibraryBindingsAlreadyInitialized` as success.
- **Pixels are RGBA** (`FPDF_REVERSE_BYTE_ORDER`), copied with `Bitmap.copyPixelsFromBuffer` into `ARGB_8888` — no swizzle.
- **Compose view**: `NibPdfView` is a `SubcomposeLayout` (not `LazyLayout`); `NibPdfViewState` exposes `zoom`, `bucket`, `scrollY`, `tileRequests`, `scrollTo`, `maxScrollY`; `PageLayout` gives page tops/sizes in content px (`pt × density × zoom`); use `nib-core::geom::PageTransform` semantics (or the Kotlin equivalent you add) to map screen → user space — never persist device coordinates. Overlays belong in `ui/` on top of each `PageItem`.
- **Tests**: `createComposeRule()` + `performTouchInput { swipeUp()/pinch() }` work; `pinch(start0, end0, start1, end1)` argument order matters (paths must not cross). 20 `swipeUp()` do not reach page 99 on a Pixel 6 — `NibPdfViewTest` scrolls programmatically afterwards. For stylus pressure injection use `uiautomator` (`2.4.1`, 2026-11-04) or `MotionEvent`-level injection via `InstrumentationRegistry` — `ui-test` cannot set pressure.
- cargo-ndk also emits `libpdfium_render-*.so`; `copyRustJniLibs<Variant>` filters to `libnib_ffi.so` only. Keep that filter. `deny.toml` has per-crate MPL-2.0 exceptions for `uniffi*` and ignores `RUSTSEC-2026-0374`.
- Emulator images are **arm64-only** (Apple Silicon host). Use AVD `nib_api34`; check `adb devices` first — an instance is often still running. Debug builds compile only the host ABI by default; CI passes `-Pnib.abis=x86_64`. Release `lto="fat"` builds take minutes per ABI — iterate with debug, run release only at the DoD gate.
- Remote CI (`.github/workflows/ci.yml`) has **never run** — nothing has been pushed. If asked to push, watch the first run (likely spots: SDK package install, emulator boot time, cargo-ndk cache key, host PDFium fetch for `cargo test`).
- Emulator `ScrollBenchmark` numbers (P90 ≈ 54 ms overrun) are far above the design target; do not tune for the emulator — M6 measures on hardware.
